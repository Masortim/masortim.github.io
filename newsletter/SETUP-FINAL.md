# Рассылка: что осталось сделать руками

Рассылка живёт в этом репозитории: страница подписки — на GitHub Pages,
серверная часть — одной функцией на Vercel, подписчики — в таблице Supabase.
Код готов и проверен. Ниже — единственное, что нельзя сделать за вас:
получить пароль приложения Gmail и вставить три значения в Vercel.

---

## Что происходит с письмами

Письма уходят **с адреса автора** — `alex.typeface@gmail.com` — по SMTP Gmail.
Получатель видит нормального отправителя, а не песочницу рассылочного сервиса.

Почему именно так:

- своего домена нет, а рассылочные сервисы (Resend и подобные) разрешают
  отправку только с проверенного домена;
- без домена они доставляют письма **исключительно владельцу аккаунта** —
  то есть проверка проходит, а реальный читатель письма не получает;

Gmail же штатно разрешает отправку от имени своего ящика по SMTP, если
включена двухэтапная аутентификация и создан пароль приложения.

Ограничение честно назовём сразу: у Gmail есть суточный лимит на отправку
(порядка 500 адресов в сутки для обычного аккаунта, около 100 для нового).
Для небольшой рассылки этого достаточно, для тысяч подписчиков понадобится
свой домен и рассылочный сервис — код переключается одной переменной.

---

## Что уже сделано за вас

- Серверная часть собирается в одну функцию и развёрнута на Vercel.
- `NEWSLETTER_FROM = Masortim <alex.typeface@gmail.com>` — адрес отправителя.
- Добавлен SMTP-транспорт: письма идут через `smtp.gmail.com:465`.
- Самодиагностика `/api/newsletter/health` понимает оба транспорта и говорит,
  чего не хватает, не раскрывая секретов.
- Отписка **удаляет** адрес из базы, а не помечает его: кого попросили забыть,
  того в базе не остаётся.
- Проба в Actions прогоняет живой цикл снаружи: подписка → письмо →
  подтверждение → отписка → проверка, что строки нет.

## Шаг 1. Пароль приложения Gmail

Это 16 символов, которые Google выдаёт вместо обычного пароля. Обычный пароль
аккаунта для SMTP не подходит и вставлять его никуда не нужно.

1. Откройте <https://myaccount.google.com/security>.
2. Включите **двухэтапную аутентификацию**, если она ещё выключена.
   Без неё Google не показывает пароли приложений вообще.
3. Откройте <https://myaccount.google.com/apppasswords>.
4. В поле названия введите `masortim newsletter` → **Создать**.
5. Google покажет четыре группы по четыре символа: `abcd efgh ijkl mnop`.
   Скопируйте их — **пробелы можно оставить, код сам их уберёт**.

Пароль показывается один раз. Если потеряли — создайте новый и удалите старый,
это безопасно.

Если страница отвечает «Настройка недоступна»:

- двухэтапная аутентификация не включена — вернитесь к пункту 2;
- аккаунт учебный или рабочий, и администратор запретил пароли приложений.
  Тогда SMTP Gmail не вариант: понадобится свой домен и рассылочный сервис
  (см. «Если понадобится домен» в конце).

## Шаг 2. Три переменные в Vercel

Vercel → проект **`masortim-newsletter`** → **Settings** → **Environment
Variables** → **Add**. Для каждой переменной отметьте все три окружения:
Production, Preview, Development.

| Key | Value | Зачем |
| --- | --- | --- |
| `NEWSLETTER_SMTP_PASS` | пароль приложения из шага 1 | **главное**: включает отправку через Gmail |
| `NEWSLETTER_SMTP_USER` | `alex.typeface@gmail.com` | ящик, от чьего имени идёт отправка |
| `NEWSLETTER_FROM` | `Masortim <alex.typeface@gmail.com>` | что видит получатель в поле «От кого» |

Остальные переменные (`SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`,
`NEWSLETTER_SITE`, `NEWSLETTER_API_BASE`, `CRON_SECRET`) уже заданы — их
менять не нужно.

`NEWSLETTER_SMTP_HOST` и `NEWSLETTER_SMTP_PORT` можно не задавать: по умолчанию
это `smtp.gmail.com` и `465`.

**Через CLI** (из корня репозитория, если установлен `vercel`):

```bash
vercel env add NEWSLETTER_SMTP_PASS production
vercel env add NEWSLETTER_SMTP_USER production
vercel env add NEWSLETTER_FROM production
```

## Шаг 3. Перевыпустить деплой

Переменные применяются только к **новым** деплоям. Изменение переменной не
перезапускает уже собранную функцию — без этого шага письма по-прежнему не
уйдут, и это самая частая причина «всё прописал, а не работает».

**Панель:** Deployments → у верхнего деплоя меню **⋯** → **Redeploy** →
подтвердить. Дождитесь статуса **Ready**.

**CLI:**

```bash
vercel --prod
```

**Или попросите агента:** он умеет перевыпускать прод в этом проекте.

## Шаг 4. Проверить самодиагностику

Откройте в браузере:

```
https://masortim-newsletter.vercel.app/api/newsletter/health
```

Ожидаемый ответ (сокращённо):

```json
{
  "ready": true,
  "blocking": [],
  "checks": {
    "transport": "smtp",
    "smtp": { "host": "smtp.gmail.com", "port": 465,
              "user": "alex.typeface@gmail.com", "passSet": true },
    "fromAddress": "Masortim <alex.typeface@gmail.com>"
  }
}
```

Если `ready: false`, в поле `blocking` будет написано, чего не хватает —
дословно, без предположений. Секретов в ответе нет, только признаки «задано».

## Шаг 5. Проверить весь цикл на себе

1. Откройте <https://masortim.github.io/newsletter/> и подпишитесь своим
   адресом (`alex.typeface@gmail.com`).
2. В течение минуты приходит письмо «Подтвердите подписку на дневник
   разработчика». Отправитель — `Masortim <alex.typeface@gmail.com>`.
   Если письма нет — проверьте «Спам» и вкладку «Промоакции».
3. Нажмите кнопку подтверждения. Откроется страница сайта с сообщением об
   успехе, и придёт второе письмо — с ссылкой на отписку.
4. В Supabase (Table Editor → `newsletter_subscribers`) у вашей строки статус
   `confirmed`.
5. Нажмите «Отписаться» внизу письма — **строка исчезнет из таблицы**.

Если письмо не пришло, точная причина видна в ответе подписки: сервер
возвращает `upstream` с кодом и именем ошибки транспорта, например
`535 auth_failed` (неверный пароль приложения) или `550 recipient_rejected`.
Адреса из ответа наружу не попадают.

## Шаг 6. Проверить выпуск, ничего не отправляя

```bash
curl -s -H "Authorization: Bearer $CRON_SECRET" \
  "https://masortim-newsletter.vercel.app/api/newsletter/digest?dry_run=1"
```

Ответ содержит записи, которые попадут в выпуск, и список получателей —
писем при этом не отправляется. `CRON_SECRET` лежит в переменных Vercel.

Без секрета тот же адрес отвечает `401` — это правильно: выпуск не должен
быть доступен всем.

Еженедельная отправка уже настроена: Vercel Cron вызывает выпуск каждое
воскресенье в 09:00 UTC.

## Шаг 7. Проверка снаружи (без вашего участия)

В репозитории есть проба, которая прозванивает живой API так же, как это
сделал бы браузер читателя:

```bash
gh workflow run newsletter-probe.yml
gh run list --workflow=newsletter-probe.yml --limit 1
```

Она проверяет: корень, отказ на битом адресе, приём валидного, защиту
выпуска, CORS для `https://masortim.github.io`, отсутствие Vercel
Authentication, самодиагностику и `newsletter/config.js` на сайте.

Когда всё настроено, в логе должно быть `HEALTH ready=true`, а шаг
**Full flow** проходит весь цикл до отписки.

Для полного цикла пробе нужны три секрета в **Settings → Secrets and
variables → Actions**:

| Имя | Значение |
| --- | --- |
| `NEWSLETTER_OWNER_EMAIL` | адрес, на который приходит письмо (`alex.typeface@gmail.com`) |
| `SUPABASE_URL` | то же значение, что в переменных Vercel |
| `SUPABASE_SERVICE_ROLE_KEY` | то же значение, что в переменных Vercel |

Без них проба проверит то, что видно снаружи, и честно напишет «пропущено»,
а не покраснеет.

## Если что-то не сходится

| Симптом | Причина и что делать |
| --- | --- |
| `blocking`: «добавьте NEWSLETTER_SMTP_PASS» | переменная не задана или деплой не перевыпущен после её добавления |
| `upstream: 535 auth_failed` | пароль приложения неверен или удалён — создайте новый (шаг 1) |
| `upstream: 550 recipient_rejected` | получателя не существует; проверьте адрес |
| письма уходят, но попадают в «Спам» | обычное дело для нового отправителя: отметьте «Не спам», репутация выправится |
| `ready: true`, но письма нет | смотрите вкладки «Спам» и «Промоакции»; проверьте, что ящик не переполнен |
| форма говорит «не удалось отправить» | откройте `/api/newsletter/health` — там написано, чего не хватает |
| отписка вернула «ссылка недействительна» | адрес уже удалён из базы — это норма после отписки |

## Если понадобится домен

Полтысячи писем в сутки хватает не всем, а у Gmail бывают периоды, когда он
не любит массовые отправки. Тогда путь такой:

1. Любой домен (не обязательно связанный с сайтом) → добавить в Resend.
2. Прописать DNS-записи, которые покажет Resend, дождаться `verified`.
3. В Vercel поменять `NEWSLETTER_FROM` на адрес с домена и добавить
   `RESEND_API_KEY`; переменную `NEWSLETTER_SMTP_PASS` удалить —
   транспорт переключится сам.

Код менять не нужно: `NEWSLETTER_TRANSPORT` можно задать явно (`smtp` или
`resend`), но по умолчанию он выбирается по наличию пароля приложения.

## Что стоит знать заранее

- **Двойное подтверждение обязательно.** Без нажатия кнопки в письме адрес
  остаётся `pending` и выпуск не получает.
- **Выпуск уходит только подтверждённым.** Отписавшиеся удалены из базы, а не
  спрятаны, поэтому случайно написать им нельзя.
- **Один адрес — одна строка.** Повторная подписка до подтверждения
  переотправляет письмо с тем же токеном, старое письмо тоже работает.
- **Язык выбирается на сайте.** Письма приходят на языке, выбранном при
  подписке: `ru` или `en`.
